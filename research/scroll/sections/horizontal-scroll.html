Horizontal Scroll

A track that scrolls sideways. Native overflow beats a hijacked vertical scroll every time.

Binding native Mechanism overflow-x with snap Cost very low Risk low

↔ drag, shift+wheel, or swipe · more to the right →

The craft

Native overflow beats a hijacked vertical scroll. The pinned-and-translated version — where scrolling down moves a track sideways — takes the page's scroll away, breaks keyboard navigation and confuses the scrollbar. Real overflow-x gives you touch, trackpad, keyboard and a real scrollbar for nothing.

scroll-state(scrollable: right) makes the affordance honest. Most horizontal tracks show a permanent "→" that lies at the end of the list. This one queries whether there is anything left to scroll, in CSS, and hides itself when there is not.

Give the track vertical padding, not the cards. A focus ring on a card inside an overflow container is clipped unless there is room for it.

Implementation

.hscroll{
  display: flex; gap: 16px;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  container-type: scroll-state;      /* so the hint can ask if more remains */
}
.hscroll > *{ flex: 0 0 min(74%, 420px); scroll-snap-align: start }

@supports (container-type: scroll-state){
  @container scroll-state(scrollable: right){ .edgehint{ opacity:1 } }
}

When not to use it

  • As a hijacked vertical scroll. It steals the page's scroll and breaks the scrollbar.
  • Without a visible affordance. A track that looks like a cut-off row reads as a bug.
  • For primary navigation. Sideways content is discovered less than vertical content.
