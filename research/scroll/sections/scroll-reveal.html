Scroll Reveal

Elements animate in as they cross the scrollport. The most-used scroll effect on the web, and the cheapest to get right.

The craft

animation-range is the whole craft. Left at its default (cover) the element is still animating when it is halfway up the screen, which reads as sluggish. entry 10% cover 38% finishes it early. The second card above is deliberately set to the sluggish range so the difference is visible rather than described.

No stagger logic is needed. Each element's position in the scrollport is the stagger — which is why a CSS reveal on a grid costs nothing while a JS one needs batching.

Scrubbed vs triggered. CSS view() is scrubbed by default: scroll up and it plays backwards, and nothing is ever left half-revealed. Triggered (IntersectionObserver, or ScrollTrigger without scrub) is better when the motion has personality — a bounce or an overshoot — that should not run in reverse.

Implementation

@keyframes reveal{
  from{ opacity:0; transform:translateY(28px) }
  to  { opacity:1; transform:translateY(0) }
}
.reveal > *{
  animation: reveal auto linear both;
  animation-timeline: view();
  animation-range: entry 10% cover 38%;   /* done well before centre screen */
}
@supports not (animation-timeline: view()){
  .reveal > *{ opacity:1; transform:none; animation:none }
}

When not to use it

  • Above the fold. Content in the initial viewport should already be there.
  • On every element. If everything reveals, nothing is emphasised and the page feels laggy.
  • On text the user is trying to read while scrolling.

Style packs

● for bento (staggered across cells — the signature entrance), minimalism (one technique for the whole page, opacity-led, short travel), neo-brutalism (snap, not float — short distance, linear, no bounce), flat and hand-drawn (paired with a per-element rotation). ⚠ for neumorphism, and the constraint is specific: never start a low-contrast control at opacity: 0. ⚠ for brutalism — permitted only with linear timing and no fade, or better, steps(1).
