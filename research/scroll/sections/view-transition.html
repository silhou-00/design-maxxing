View Transition

Motion between views rather than within a scrolling page. The one technique here that is not a scroll technique — which is exactly why it fills a hole.

Binding triggered by navigation or a DOM change Mechanism View Transition API Cost very low Risk low

Click a tile. The tile and the detail panel share a view-transition-name, so the browser morphs one into the other — it is not a crossfade, it is the same element in two places.

DETAIL

Opened without a route change, a library, or a single line of animation code — document.startViewTransition() and one shared name.

checking support…

Why this is in a scroll folder. Every other technique here animates while you scroll. This one animates when you arrive — and the corpus had no entry for it at all. For a narrative that spans routes, page-to-page motion was the missing half.

Cross-document needs no framework and no JavaScript: two lines of CSS give a multi-page site animated navigation.

The craft

Names must be unique per document. Two elements sharing a view-transition-name throws rather than degrading — which is why the demo above assigns the name to the clicked tile only, and clears it afterwards.

Reduced motion is not automatic. This is page-level motion under §6 and needs the same treatment as parallax: strip every name, or branch in JS and update the DOM directly. The "update without a transition" button above takes that second path.

It has the best failure mode in this folder. Where the API is unsupported the DOM simply updates instantly — the web working normally. Compare that to a reveal stuck at opacity: 0.

It is the honest answer for brutalism and neumorphism, the two packs where nearly every scroll technique is ✗. A navigation transition is not a scroll effect, so the objection to scroll polish does not reach it.

Implementation

// same document
document.startViewTransition(() => { updateTheDOM() });

// give the two elements the same name and the browser morphs between them
tile.style.viewTransitionName = 'card';
detailArt.style.viewTransitionName = 'card';   // names must be UNIQUE per document

/* cross-document — no framework, no JS at all */
@view-transition { navigation: auto }

@media (prefers-reduced-motion: reduce){
  *{ view-transition-name: none !important }
}

When not to use it

  • On every navigation. A transition on a link followed fifty times becomes friction.
  • To disguise a slow load — it animates the arrival, it does not make it sooner.
  • With a duplicate view-transition-name. It throws rather than degrading.
