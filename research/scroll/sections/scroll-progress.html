Scroll Progress

A bar that fills as the document scrolls. The cheapest technique in the catalogue, and the only one WCAG exempts from reduced motion.

Two indicators, one timeline

The bar at the top and the ring at the bottom right are both bound to scroll(root block). Neither reads the scroll position in JavaScript; both are driven by the compositor.

This is the only technique in the catalogue that survives reduced motion. WCAG 2.3.3 exempts motion that conveys position, and a progress indicator conveys nothing else. Collapse it and you have removed information rather than decoration.

Why the bar is a transform

It scales on the X axis from a left origin. Animating width would produce the same picture and force layout on every frame — the exact failure engine.md §6 exists to prevent.

The ring uses stroke-dashoffset with pathLength="1", which normalises the path so the offset runs cleanly from 1 to 0 regardless of the circle's real circumference.

Both indicators track the document, so they reach 100% exactly when this page ends.

A progress bar is also the honest fallback for a pack where almost every other technique is ✗. It costs nothing, it breaks nothing, and it is genuinely useful.

Swiss uses it as a solid red bar four to eight pixels tall, straight out of the poster vocabulary. Editorial uses it because the reading indicator was invented for exactly this content.

The craft

This is the one technique that survives prefers-reduced-motion. WCAG 2.3.3 exempts motion that conveys position; engine.md §6 states the exception in as many words. Collapsing a progress bar removes information, not decoration.

Scale, never width. The bar animates transform: scaleX() from a left origin. Animating width looks identical and forces layout every frame.

pathLength="1" on the ring normalises the SVG path so stroke-dashoffset runs 1 → 0 without anyone computing a circumference.

Implementation

.progress{
  position: fixed; inset: 0 0 auto 0; height: 6px;
  transform-origin: 0 50%;
  animation: prg auto linear both;
  animation-timeline: scroll(root block);
}
@keyframes prg{ from{ transform:scaleX(0) } to{ transform:scaleX(1) } }

@supports not (animation-timeline: scroll()){ .progress{ display:none } }

When not to use it

  • On a short page. If there is nothing to track, the bar is decoration pretending to be information.
  • As a second progress signal alongside a step indicator — pick one.
  • Collapsed under reduced motion. It is exempt, and removing it removes information.
