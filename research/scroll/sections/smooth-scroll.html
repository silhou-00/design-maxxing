Smooth Scroll

Inertial, lerped scrolling. The only technique here that changes how the whole page feels rather than how one element behaves.

Binding continuous Mechanism a library that hijacks native scroll Cost medium — a rAF loop, always Risk high
This section deliberately does not demonstrate the effect. Smooth scroll is global: enabling it here would change how every other section on this site behaves, and would hijack the scroll of a page whose whole purpose is to demonstrate scroll. That refusal is the demonstration.

What it actually is

A library intercepts the wheel and touch events, prevents the native scroll, and animates a transform on the page body toward the target position on a requestAnimationFrame loop. It is the one technique in this catalogue that is not a CSS scroll-driven animation and cannot be.

Why three packs ban it outright

Brutalism rates it ✗ emphatically: the browser's honest defaults are the entire thesis, so lerped scroll is the single most anti-brutalist addition available. Neo-brutalism because inertia is soft and the style is hard — its signature interaction is an instant translate(4px,4px). Swiss because the style is objective and precise, and inertia is neither.

The alternative almost nobody reaches for

You usually want smoothed animation, not smoothed scrolling. Lenis smooths the whole page's scroll position — a global feel change, and the reason this technique carries so many accessibility caveats. Anime.js sync: 0.25 and GSAP scrub: 1 smooth one animation's catch-up and leave native scroll untouched. Most of the same perceived liquidity, none of the hijack.

If you ship it anyway

Disable it entirely under prefers-reduced-motion: reduce — a lerped scroll is precisely the vestibular trigger WCAG 2.3.3 addresses. Keep the scrollbar honest, never lengthen the page to buy runway, and test keyboard paging: a hijacked scroll frequently breaks Page Down and focus scrolling.

The craft

The refusal is the point. Every other section here demonstrates its technique. This one cannot: smooth scroll is global, so enabling it would change every other page on this site and hijack the scroll of a document whose purpose is to demonstrate scroll.

Most requests for "smooth scroll" are requests for smoothed animation. That is a different thing, it is cheaper, and it does not take the page's scroll away — sync: 0.25 or scrub: 1 rather than a scroll-hijacking library.

It is the only technique here that is not CSS. Everything else in this folder runs on a compositor-driven timeline. This one is a requestAnimationFrame loop, permanently.

Implementation

/* CSS gives you the safe part for free — anchor jumps only, and it
   already honours the user's motion preference. */
html{ scroll-behavior: smooth }
@media (prefers-reduced-motion: reduce){ html{ scroll-behavior: auto } }

/* What you probably wanted instead — smooth the ANIMATION, not the scroll: */
// anime.js:  autoplay: onScroll({ sync: 0.25 })
// GSAP:      scrollTrigger: { scrub: 1 }

When not to use it

  • As a default. It is a deliberate, global, high-risk choice.
  • In brutalism, neo-brutalism or swiss — all three rate it ✗ for stated reasons.
  • Without a reduced-motion escape. A lerped scroll is a vestibular trigger.
  • Alongside scroll snap. Two systems fighting for the scroll position.

Style packs

✗ for brutalism, neo-brutalism and swiss, each for a reason rooted in the style rather than in taste. ⚠ everywhere else — permitted, never assumed. There is no pack in the catalogue for which this is a core fit.
