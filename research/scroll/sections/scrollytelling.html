Scrollytelling

A sticky visual holds while text scrolls beside it, and the visual changes at each step. Content sequencing, not a visual device.

The visual holds, the text moves

The panel on the left is position: sticky. Each figure inside it is bound to its own step's view progress, so the visual changes as the argument does.

It is content sequencing

Scrollytelling is not an effect bolted onto a page. The steps are the structure — which is why the technique file calls it narrative rather than a visual device.

The column must be much taller

Each step is 78vh here. If the text column is not substantially taller than the sticky panel, the pin barely holds and the whole thing reads as a glitch.

Steps, not a continuous scrub

Each figure crossfades over its own step rather than one animation running the length of the piece. That keeps a step readable while it is on screen.

The craft

How this differs from a pinned scene. A pinned scene holds one visual while content passes. Scrollytelling changes the visual at each step — four figures here, each bound to its own step's progress. The visual is the argument's illustration, so it has to move when the argument does.

The steps are the structure. This is the one technique in the catalogue where the content model comes first: you are writing a sequence of claims, and the visual answers each one. Reaching for it without that sequence produces a sticky image and some paragraphs.

Each step owns its own timeline. One animation spanning the whole piece would leave the visual mid-transition while a step is being read. Per-step view() ranges with a hold in the middle (18% → 82% here) keep each state stable while its text is on screen.

The fallback must show something. With every step at opacity: 0, an unsupported timeline leaves an empty box. Showing the first figure is a valid degraded state; an empty panel is not.

Implementation

.viz{ position: sticky; top: 12vh }        /* the visual holds */
.fig{
  position: absolute; inset: 0; opacity: 0;
  animation: step auto linear both;
  animation-timeline: view();             /* each step, its own progress */
  animation-range: cover 0% cover 100%;
}
@keyframes step{ 0%{opacity:0} 18%{opacity:1} 82%{opacity:1} 100%{opacity:0} }

@supports not (animation-timeline: view()){
  .fig{ opacity:0; animation:none } .fig.f0{ opacity:1 }   /* show something */
}

When not to use it

  • Without a real step sequence. Otherwise it is a sticky image with paragraphs next to it.
  • When the text column is shorter than the sticky visual — the pin will not hold.
  • For content the reader may want to skim. Each step demands a full scroll.
